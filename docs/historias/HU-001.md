# HU-001: Control básico del temporizador

## Estado

**Borrador. Pendiente de contrastar con el enunciado original antes de su aprobación.**

Esta historia no autoriza planificación técnica ni implementación.

## Historia de usuario

Como estudiante de Academia Cotopaxi, quiero iniciar, pausar, reanudar y reiniciar con confirmación el temporizador para controlar una fase Pomodoro según mis necesidades.

## Objetivo

Permitir el control directo del temporizador y conservar un tiempo restante coherente en cada transición.

## Alcance confirmado para revisión

- Mostrar el tiempo restante y el estado del temporizador.
- Iniciar manualmente una fase disponible.
- Pausar una fase en curso.
- Reanudar una fase pausada desde el tiempo conservado.
- Solicitar confirmación antes de reiniciar.
- Cancelar el reinicio sin alterar el estado ni el tiempo.
- Reiniciar la fase confirmada a su duración completa aplicable.

## Requisitos EARS preliminares

- **HU-001-R01 (ubícuo):** La aplicación deberá mostrar el tiempo restante y el estado actual del temporizador.
- **HU-001-R02 (dirigido por evento):** Cuando el usuario inicie una fase disponible, la aplicación deberá comenzar la cuenta regresiva desde la duración aplicable.
- **HU-001-R03 (dirigido por evento):** Cuando el usuario pause una fase en curso, la aplicación deberá detener la cuenta regresiva y conservar el tiempo restante.
- **HU-001-R04 (dirigido por evento):** Cuando el usuario reanude una fase pausada, la aplicación deberá continuar la cuenta regresiva desde el tiempo restante conservado.
- **HU-001-R05 (dirigido por evento):** Cuando el usuario solicite reiniciar el temporizador, la aplicación deberá pedir confirmación antes de modificar la fase actual.
- **HU-001-R06 (dirigido por evento):** Cuando el usuario cancele la confirmación de reinicio, la aplicación deberá conservar el estado y el tiempo restante existentes.
- **HU-001-R07 (dirigido por evento):** Cuando el usuario confirme el reinicio, la aplicación deberá restaurar la duración completa aplicable de la fase actual.
- **HU-001-R08 (dependiente de estado):** Mientras el temporizador no esté en curso, la aplicación no deberá descontar tiempo.
- **HU-001-R09 (ubícuo):** La aplicación deberá comunicar el estado y los controles del temporizador de forma accesible y sin depender únicamente del color.

## Criterios de aceptación preliminares

### HU-001-CA01: Inicio

**Dado** que una fase está disponible y todavía no está en curso,  
**Cuando** el usuario selecciona iniciar,  
**Entonces** el temporizador cambia a ejecución y comienza a descontar desde la duración aplicable.

### HU-001-CA02: Pausa

**Dado** que el temporizador está en ejecución,  
**Cuando** el usuario selecciona pausar,  
**Entonces** el temporizador conserva el tiempo restante y deja de descontarlo.

### HU-001-CA03: Reanudación

**Dado** que el temporizador está pausado con un tiempo restante conservado,  
**Cuando** el usuario selecciona reanudar,  
**Entonces** la cuenta regresiva continúa desde ese tiempo sin volver a la duración completa.

### HU-001-CA04: Solicitud de reinicio

**Dado** que existe una fase actual,  
**Cuando** el usuario selecciona reiniciar,  
**Entonces** la aplicación solicita una confirmación antes de cambiar el estado o el tiempo restante.

### HU-001-CA05: Cancelación del reinicio

**Dado** que la confirmación de reinicio está visible,  
**Cuando** el usuario cancela la acción,  
**Entonces** la fase conserva el mismo estado y tiempo restante que tenía antes de solicitar el reinicio.

### HU-001-CA06: Confirmación del reinicio

**Dado** que la confirmación de reinicio está visible,  
**Cuando** el usuario confirma la acción,  
**Entonces** el tiempo vuelve a la duración completa aplicable de la fase actual.

### HU-001-CA07: Estado detenido

**Dado** que el temporizador está disponible o pausado,  
**Cuando** transcurre tiempo sin que el usuario lo inicie o reanude,  
**Entonces** el tiempo restante no disminuye.

### HU-001-CA08: Accesibilidad del control

**Dado** que el usuario consulta el temporizador con tecnología de asistencia,  
**Cuando** recorre el tiempo, el estado y las acciones disponibles,  
**Entonces** puede identificar cada elemento mediante su nombre, rol y estado sin depender únicamente del color.

## Dependencias
