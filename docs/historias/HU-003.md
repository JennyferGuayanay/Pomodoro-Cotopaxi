# HU-003: Conservación y recuperación del temporizador

## Estado

**Borrador. Pendiente de contrastar con el enunciado original antes de su aprobación.**

Esta historia no autoriza planificación técnica ni implementación.

## Historia de usuario

Como estudiante de Academia Cotopaxi, quiero conservar el estado del temporizador y recuperar el tiempo correcto después de bloquear el celular o cerrar y reabrir la aplicación para no perder el progreso de la fase.

## Objetivo

Reconstruir el estado temporal correcto sin asumir que la aplicación permaneció activa en pantalla.

## Alcance confirmado para revisión

- Conservación del estado necesario del temporizador.
- Recuperación después de bloquear y desbloquear el celular.
- Recuperación después de cerrar y reabrir la aplicación.
- Cálculo del tiempo restante según el tiempo real transcurrido cuando la fase estaba en ejecución.
- Conservación del tiempo restante cuando la fase estaba pausada o pendiente de inicio manual.
- Funcionamiento local sin conexión a Internet.

## Requisitos EARS preliminares

- **HU-003-R01 (dirigido por evento):** Cuando el celular se bloquee o la aplicación se cierre, la aplicación deberá conservar la información necesaria para recuperar el estado del temporizador.
- **HU-003-R02 (dirigido por evento):** Cuando el usuario vuelva a una fase que estaba en ejecución, la aplicación deberá calcular el tiempo restante descontando el tiempo real transcurrido durante la ausencia.
- **HU-003-R03 (dirigido por evento):** Cuando el usuario reabra la aplicación, la aplicación deberá recuperar la fase y el estado conservados.
- **HU-003-R04 (dependiente de estado):** Mientras una fase esté pausada, el tiempo transcurrido con el celular bloqueado o la aplicación cerrada no deberá reducir el tiempo restante.
- **HU-003-R05 (dependiente de estado):** Mientras una fase esté pendiente de inicio manual, el tiempo transcurrido con el celular bloqueado o la aplicación cerrada no deberá reducir su duración.
- **HU-003-R06 (dirigido por evento):** Cuando el tiempo de una fase en ejecución se agote durante la ausencia, la aplicación deberá considerar esa fase terminada y dejar la siguiente fase pendiente de inicio manual conforme a HU-002.
- **HU-003-R07 (dependiente de estado):** Mientras el dispositivo no tenga conexión a Internet, la conservación y recuperación deberán funcionar localmente.
- **HU-003-R08 (comportamiento no deseado):** Si el estado conservado no puede recuperarse correctamente, la aplicación no deberá bloquearse ni mostrar un tiempo negativo o imposible.

## Criterios de aceptación preliminares

### HU-003-CA01: Recuperación después de bloqueo

**Dado** que una fase está en ejecución con tiempo restante,  
**Cuando** el usuario bloquea el celular y vuelve antes de que finalice la fase,  
**Entonces** la aplicación muestra el tiempo restante calculado al descontar el tiempo real transcurrido.

### HU-003-CA02: Recuperación después de cerrar y reabrir

**Dado** que una fase está en ejecución con tiempo restante,  
**Cuando** el usuario cierra y reabre la aplicación antes de que finalice la fase,  
**Entonces** la aplicación recupera la misma fase en ejecución con el tiempo real restante.

### HU-003-CA03: Conservación de una pausa

**Dado** que una fase está pausada con un tiempo restante,  
**Cuando** el usuario bloquea el celular o cierra y reabre la aplicación,  
**Entonces** la aplicación recupera la fase pausada con el mismo tiempo restante.

### HU-003-CA04: Conservación de una fase pendiente

**Dado** que una fase está disponible y pendiente de inicio manual,  
**Cuando** el usuario bloquea el celular o cierra y reabre la aplicación,  
**Entonces** la aplicación recupera esa fase sin haber descontado tiempo.

### HU-003-CA05: Finalización durante la ausencia

**Dado** que una fase está en ejecución y su tiempo restante vence durante el bloqueo o cierre,  
**Cuando** el usuario vuelve a la aplicación,  
**Entonces** la fase aparece terminada y la siguiente fase definida por HU-002 permanece pendiente de inicio manual.

### HU-003-CA06: Recuperación offline

**Dado** que el dispositivo no tiene conexión a Internet,  
**Cuando** el usuario bloquea o cierra y luego vuelve a la aplicación,  
**Entonces** el estado y el tiempo se recuperan localmente con el mismo comportamiento funcional.

### HU-003-CA07: Estado no recuperable

**Dado** que la información conservada falta o no es válida,  
**Cuando** la aplicación intenta recuperar el temporizador,  
**Entonces** no se bloquea ni presenta un tiempo negativo o imposible y adopta un estado seguro todavía pendiente de definir.
